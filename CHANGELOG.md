# Changelog

## Unreleased - 2026-09-09 production hotfix

### Fixed

- full-day archive jobs use a maintenance database pool without the 10-second
  request-path command timeout;
- ingestion runs persist an indexed `latest_observed_at` watermark, allowing
  stack smoke and soak gates to check freshness without scanning all historical
  partitions;
- archive restore checks use the cleanup-backed archive volume instead of a
  128 MiB tmpfs, so real production Parquet objects can be verified.

### Verified

- ARM64 stack, realtime persistence, Valkey cache and stable source fingerprint;
- OCI Object Storage smoke plus a 4,627,753-row archive and full restore check;
- fresh 24-hour soak started at `2026-09-09T17:23:55.635815Z`.

### Safety

- `DESTRUCTIVE_RETENTION_ENABLED=false` remains unchanged;
- no PostgreSQL partition was removed.

## 0.7.1 — 2026-09-03

### Fixed

- Rio realtime requests now include the UTC `dataInicial`/`dataFinal` window
  required by the current official endpoint contract;
- successful requests advance an in-memory cursor with bounded overlap, while
  failures retain the prior cursor for safe retry;
- recovery windows are capped at five minutes so an outage cannot trigger an
  unbounded response after service recovery.

### Changed

- production polling defaults to 60 seconds, with a 120-second bootstrap and
  30-second overlap, reducing duplicate downloads and database conflict work;
- the source timeout is 20 seconds and the bounded JSON response limit is 32 MiB.

### Safety

- request query parameters are generated by the adapter and encoded by HTTPX;
- hostname allowlisting, response limits, deduplication and retention safety
  remain enforced;
- `DESTRUCTIVE_RETENTION_ENABLED=false` remains unchanged.

## 0.7.0 — 2026-09-03

### Added

- secure, bounded downloader for the official Rio static GTFS feed;
- content-addressed GTFS snapshot manifest with SHA-256, source, attribution,
  license, fetch time and observed file/column inventory;
- strict GTFS ZIP validation for required files and columns, CRC/readability,
  path traversal, encryption, symbolic links, duplicate names, member count,
  compressed size, expanded size and suspicious compression ratios;
- hardened maintenance canary for validating the feed from the production VPS.

### Scope

- static GTFS is a parallel input for the future ETA/Confidence milestone;
- it does not make the realtime ingestion gate pass and it does not start the
  24-hour realtime soak window.

### Safety

- `DESTRUCTIVE_RETENTION_ENABLED=false` remains unchanged;
- GTFS acquisition has a dedicated hostname allowlist and never follows an
  unchecked redirect.

## 0.6.5 — 2026-09-02

### Added

- first production deployment on the Oracle ARM64 VPS;
- private OCI Object Storage bucket and S3-compatible credentials;
- restartable soak watcher that starts its 24-hour window only after the first
  successful cycle with persisted/cached positions and a contract fingerprint;
- production deployment evidence for the ARM64 stack, storage and restore gate.

### Fixed

- boto3 checksum policy for OCI S3-compatible endpoints that reject optional
  `aws-chunked` uploads;
- non-root ownership of the archive spool volume.

### Verified

- PostgreSQL 17.11 with PostGIS 3.6.4, Valkey 8.1.9 and API readiness;
- persistent database/cache volumes across container restarts;
- Object Storage upload, download, SHA-256 comparison and smoke-object cleanup;
- remote Parquet restore with matching row count, byte size and SHA-256.

### Safety

- `DESTRUCTIVE_RETENTION_ENABLED=false` remains enforced;
- the 24-hour soak is armed but does not count upstream HTTP 500 time as a
  valid observation window.

## 0.6.0 — 2026-09-01

### Added

- production Compose hardened for the initial Oracle VPS;
- ARM64-safe PostgreSQL/PostGIS build based on the official PostgreSQL image;
- 24-hour ingestion soak gate and operational evidence model;
- stack smoke command for Postgres, Valkey and recent Rio GPS evidence;
- object-store upload/download smoke;
- remote Parquet restore verification;
- deployment, preflight, status and operational runbooks;
- CI cross-build gate for the database image (`amd64` + `arm64`);
- tests that guard production network exposure and retention defaults.

### Changed

- realtime polling cadence is now anchored to cycle start, so source latency does not accumulate on top of the configured interval;
- Valkey production deployment requires authentication;
- API and worker containers run read-only with reduced Linux capabilities in production;
- database/cache are not published on host interfaces.

### Safety

- destructive retention remains disabled;
- public API exposure remains disabled pending the edge-security milestone;
- brand remains technically decoupled from package/bundle identifiers.
